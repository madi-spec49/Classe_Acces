# Classe Accès — Documentation technique (Portfolio, Stage 4)

Plateforme de cours à distance pour une association scolaire

Ce document fait partie de la documentation technique de **Classe Accès**. Le MVP s'appuie sur une stack FastAPI + SQLAlchemy + PostgreSQL + JWT, avec une interface HTML/JavaScript native.

## 5. Spécifications des API

### 5.1 API externes

Le MVP n'utilise aucune API externe.

| API | Statut | Description |
| --- | --- | --- |
| **HelloAsso** | Reportée | Formulaires de cotisation et webhook de paiement, pensés pour les associations françaises (voir `7. Roadmap Phase Future.md`) |
| **API Zoom** | Écartée | Le lien Zoom est saisi manuellement par le staff : aucune dépendance externe indispensable |

### 5.2 API internes (REST, JSON)

L'API est une API **REST**, exposée par FastAPI sous le préfixe `/api`. Les requêtes et les réponses sont au format **JSON**. La documentation interactive est générée par FastAPI sur `/docs`.

**Conventions communes :**

- **Authentification** : jeton JWT dans l'en-tête `Authorization: Bearer <token>`, sur toutes les routes sauf `POST /api/auth/login` et `GET /health`.
- **Rôles** : `student`, `parent`, `teacher`, `staff`, vérifiés par la dépendance `require_role`.
- **Codes de réponse** : `200` succès (y compris les créations), `400` requête invalide (élève hors niveau, email déjà utilisé, professeur qui a encore des cours), `401` identifiants incorrects ou jeton invalide ou expiré, `403` rôle ou propriété insuffisants, `404` ressource introuvable, `422` données invalides (horaires incohérents, valeur hors liste, champ manquant).
- **Absence de jeton** : FastAPI répond directement `403` quand l'en-tête `Authorization` est absent.

#### 5.2.1 Règles de contrôle des rôles à la création de compte

- Il n'existe **pas d'inscription publique**. Les comptes élève, parent et professeur sont créés uniquement par le staff.
- Le rôle du nouveau compte est **fixé par la route** (`/api/staff/teachers` crée un `teacher`, `/api/parents` crée un `parent`, `/api/staff/students` crée un `student`). Il n'est jamais lu dans le corps de la requête, ce qui empêche une élévation de privilège.
- Aucune route ne crée de compte `staff`. Le premier compte staff se crée avec le script `scripts/create_staff.py`, depuis la machine qui a accès à la base.
- Un compte staff ne peut être ni supprimé ni réinitialisé par les routes de l'API.

#### 5.2.2 Règles d'accès aux données d'un élève

| Donnée | Élève | Parent | Professeur | Staff |
| --- | --- | --- | --- | --- |
| Assiduité d'un élève | la sienne | ses enfants | non | oui |
| Progression d'un élève | la sienne | ses enfants | élèves de son niveau | oui |
| Assiduité d'une séance | non | non | ses cours | oui |
| Liste des cours et des séances | son niveau | non | ses cours | oui |

Un parent n'a donc accès ni aux cours ni aux séances, seulement au suivi de ses enfants.

#### 5.2.3 Règles métier

- **Niveau** : un professeur ne peut saisir l'assiduité ou la progression que pour un élève du **niveau de son cours**, sinon la réponse est `400`.
- **Propriété** : un professeur ne saisit que dans **ses propres cours**, sinon la réponse est `403`.
- **Assiduité unique** : une seule présence par élève et par séance ; une seconde saisie met à jour la première.
- **Suppression** : supprimer un cours supprime ses séances, présences et progressions. Un professeur qui a encore des cours ne peut pas être supprimé.

### 5.3 Documentation interactive

FastAPI génère la documentation OpenAPI (Swagger) sur `http://127.0.0.1:8000/docs`, où chaque route peut être testée avec le bouton *Authorize* et un jeton obtenu par `POST /api/auth/login`.
